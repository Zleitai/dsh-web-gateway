# V2 架构

## 产品体验

用户安装电脑端连接器后获得一个固定 HTTPS 地址。手机打开该地址，完成入口登录和
DSH 自身认证后，直接加载电脑上同一个 DSH Web 应用。电脑与手机因此天然共享会话、
模型、设置、工具、审批和后续 DSH 功能。

V2 不再实现独立会话协议、聊天记录投影或第二套审批界面。

## 请求路径

```text
手机浏览器
  -> 固定 HTTPS 地址
  -> 入口身份验证
  -> 出站隧道
  -> 127.0.0.1 上的认证入口
  -> 127.0.0.1 上的 DSH Web
```

首个部署可使用 Cloudflare Access 与 Named Tunnel。连接器负责进程管理和配置，
普通用户不接触 tunnel token、端口、YAML 或命令行。后续可以替换边缘服务，浏览器与
DSH 之间的产品行为不应依赖供应商专有接口。

## DSH 接入

DSH `0.1.5-rc.1` 的 Web profile 提供 `--host`、`--port`、`--no-open` 和
`--trusted-host`。V2 使用受支持的 `trusted-host` 配置允许固定公网 authority，
不再像 V1 那样把 Host 与 Origin 改写为回环地址。

连接器需要：

1. 检测 DSH 版本和命令能力；
2. 以回环地址启动或发现 DSH Web；
3. 传入精确的固定公网 authority；
4. 读取 DSH 输出的进程认证 URL，但不写入普通日志；
5. 为首次授权生成公网 origin 下的一次性短期配对码，不把 DSH 启动凭据发往公网；
6. 入口登录完成后在本机消费配对码，并通过 DSH 官方认证端点兑换浏览器 Cookie；
7. 监测 DSH 和隧道健康状态，不擅自取消任务或删除会话；
8. 在升级前运行真实浏览器、WebSocket、认证和会话验收。

连接器不得读取模型凭据、改写会话日志或提供通用本机反向代理。

## 移动布局

手机使用 DSH 原生网页。移动适配作为可独立关闭的增强层，只处理布局、触摸区域、
安全区域和窄屏导航，不改变认证、会话或工具调用。

选择器优先使用稳定语义属性和 DSH 提供的扩展点。若只能依赖构建类名，则必须按
DSH 版本打包并进行截图测试。样式不兼容只能降低布局质量，不能阻止 DSH 启动。

## 安全边界

- DSH 和本地管理接口只绑定回环地址。
- 隧道由电脑主动向外连接，不开放路由器入站端口。
- 固定公网地址先经过入口认证，再进入 DSH 的进程令牌与签名 Cookie 认证。
- 不在 URL 查询日志、访问日志、错误报告或监控中保存 DSH token。
- WebSocket 与普通 HTTP 使用同一认证和 origin 策略。
- 连接器只允许代理预先声明的 DSH 本地端口，不接受任意目标地址。
- 更新或重启连接器不终止 DSH 中已经运行的任务。

## 暂不纳入 V2 首个里程碑

- 独立 PWA 聊天客户端；
- 自定义端到端会话协议；
- 将 DSH ACP 转换为另一套移动聊天产品；
- 文件同步、通知服务和原生手机应用；
- 自动切换生产域名。
